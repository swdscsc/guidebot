## 1. 简历怎么写（诚实版，经得起追问）

**GuideBot｜智能导盲机器人软件栈（个人项目，纯仿真）**

- 复刻商用辅具 Glide 技术栈，构建**感知→规划→控制→人机反馈**的实时闭环仿真系统，Python 零第三方依赖实现（只用 `math / random / dataclasses / json`）；
- 针对"无动力轮、前向速度由人提供"这一特殊控制约束，由 `ψ̇ = v·tan(δ)/L` 推导并实现**低速可控性门限**与**制动距离不等式** `d_free ≥ v²/(2μg) + v·T_latency + margin`；15 回合标准评测中**零碰撞 / 零踩空 / 零悬空撞击**，完成率 86.7%；
- 设计 5 类场景 × 3 种子的可复现 benchmark，共 9 组对照实验逐个归因：去除悬空感知层 → 悬空撞击 **18.4 次/km**；去除下视探头 → 踩空 **13.9 次/km**；压力条件下运动预测使碰撞率 **5.56 → 1.94 次/km（−65%）**；
- 定位并修复十余类真实失效：采样器"原地绕圈刷分"、人机延迟反馈的**指令饥饿**、规划器偷看真值导致的 **Ablation 失真**、线性净空代价导致的**"宁可撞上也不绕"**、世界未做时间参数化导致的**动态障碍空转**、静止时**规划视野坍缩**、转弯半径与前瞻距离失配、过激刹车判据造成的**死锁**，以及多个实现之间**枚举语义分叉**；
- **MATLAB / Simulink 工程化链路（MBD）**：脚本自动生成 Simulink 模型（`new_system` / `add_block` / Stateflow API），系统拆成"AI 主机（`coder.extrinsic`，可变尺寸）"与"安全 MCU（全标量，可代码生成）"两条链，安全层用 **Stateflow 五态状态机**表达并由 **MATLAB Coder 生成 ANSI C**（无动态内存）；完成 **SIL** 交叉验证（Python ↔ MATLAB 逐帧 bit-level 一致，**2617 帧零偏差**）、**MIL** 独立复现（8 变体 × 15 场景，结论同向）、**Simulink 数值仿真**（33.6 s 抵达终点）与模型静态结构验证（悬空输入端口 0、Stateflow 5 态 12 转移、反馈闭环成立）。

## 2. 面试"防追问"模板

**问：这是实机吗？**
→ 不是，是纯仿真。我的定位很明确：**验证算法与评测体系**，因为这块才是产品真正的技术壁垒。感知接口按"可直接换成 Depth Anything V2 的 ONNX 推理"来设计（`Observation` 结构不变，下游零改动）。

**问：完成率 86.7% 而不是 100%，剩下 13% 呢？**
→ 是两个回合走进了"必须停下等行人过去"的僵局。我保留了这个数字，因为它量化了安全预算与通行效率的权衡；而且压力实验证明：去掉安全层虽然完成率 100%，碰撞率却从 1.94 涨到 3.38 次/km。做安全关键系统，这个取舍必须摆在桌面上。

**问：Python 侧为什么不用 numpy / PyTorch？**
→ 算法难度不在库调用，在公式推导和实验设计——用 numpy 不会让这套东西变难。零依赖换来的是**任何人 clone 下来就能复现全部数字**，这对评审价值更大。技术栈广度我用 MATLAB/Simulink 那条链补：代码生成、状态机、形式化验证，不是往 Python 里塞几个库能换来的。

**问：为什么要做 MATLAB 这一遍？Python 跑一次不就完了？**
→ 那是两个不同的可信度问题。Python 跑一次只说明"这组随机数下能跑通"；我做了三层：**SIL**（同一套控制律两种语言实现逐帧 bit-level 一致，2617 帧零偏差）、**MIL**（换独立实现重跑，8 个变体结论同向）、**代码生成**（安全层能进 MCU）。只有两层独立实现给出同向结论，才能排除"结论是随机数巧合"。

**问：Simulink 模型是手画的吗？**
→ 不是，脚本生成的。参数和世界数据从 `params.json` / `scenarios.json` 注入，模型里不存在手抄的常数——改算法就重新生成、重跑回归。模型本身也是可版本管理的产物。

**问：Simulink 那条链跑到哪一步了？**
→ 完整链路都跑通了：模型由脚本生成并通过静态结构验证，数值仿真也出结果（mixed_1 场景 33.6 s 抵达终点，平均速度 1.15 m/s），安全层的 ANSI C 也生成了。唯一没做的是**代码生成后在目标板上跑**（本机没有 C 编译器，生成的 C 未编译执行）——这一点我在 README 的"已知局限"里如实写了。

**问：最有技术含量的一点是什么？**
→ 约束本身：`v` 由人提供、不可命令。由此推出横移能力 `(v·T)²·tan(δ_max)/(2L)` 正比于 v²，所以人一停下转向权限就归零——系统必须"诚实认怂"而不是硬撑。这条同时解释了为什么刹车判据必须带 TTC 门限，否则一刹车就永久死锁。

**问：MATLAB 那层最难的 bug 是哪个？**
→ Simulink 侧人模型把提示词 `cue` 当数值区间判断（`cue>3.5` 就停），把"提示前方有悬空障碍(cue=5)"吃成了"罚站立定"，人被永久停死；Python/MIL 侧用精确枚举所以没事。逐帧 trace 才看出来：**每一侧单独看都没问题，合起来行为分叉**。这条很能说明"多个实现"这件事的代价。

**问：和真实机器人比还差什么？**
→ 三件：sim-to-real 的传感器噪声标定、时延分布测量、真实用户实验。都写进 README 的 Roadmap 了。

## 3. 演示顺序建议（5 分钟版）

1. 开 `results/replay.html`——先让评审"看见"闭环在跑（10 秒建立直觉）；
2. 讲那个约束 `ψ̇ = v·tan(δ)/L`，v 由人给（这是所有设计决策的根）；
3. 跳到压力实验那张表——只有它能证明安全层真的值钱；
4. 展示 `ml → slx` 链路与生成的 C 代码；
5. 收尾讲"我删掉了什么为什么"（信息隔离那个 bug）——体现你有证伪意识。
